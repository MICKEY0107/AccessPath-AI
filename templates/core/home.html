How it works

  1. Run the journey. An AI planner (or a scripted plan) proposes one key press at a time; a fixed policy approves each before the browser presses it.
  2. Check every step. Visible and unhidden focus, control names, skip links, focus order, focus that changes the page, your team's own rules, and axe-core when installed.
  3. Confirm before blaming. If the task fails, keyboard-only probes re-test the control. Only a confirmed barrier counts against the site; otherwise the report says the AI or the provider failed.
  4. Report and fix. A verdict in plain words for product managers, findings by WCAG rule, and — with the code linked — the file, the line and a patch, which can be re-checked on a copy.

Safety boundary

Evaluations never log in, submit forms, send messages, or make payments. Real-website runs are read-only. Linked repositories are copied read-only and never run. Results do not claim full WCAG conformance.
